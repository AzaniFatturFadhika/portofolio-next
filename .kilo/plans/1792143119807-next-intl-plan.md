# Bagian 1 — next-intl — teks terpisah dari UI (id + en, default id, prefix always)

## Tujuan
Terapkan `next-intl` di repo portfolio Next.js 16 App Router sehingga seluruh string UI dikelola di `messages/id.json` + `messages/en.json`, terpisah dari komponen. Routing locale eksplisit: `/id/...` dan `/en/...`, default `id`.

## Keputusan (disepakati)
- Locale: `id` + `en`, default `id`.
- Prefix: `always` — kedua locale selalu berprefix (`/id`, `/en`); root `/` redirect ke `/id` via middleware.
- Asumsi cakupan (pertanyaan scope di-dismiss user): **penuh incl. data** — semua label UI + `profile`, `projects`, `experience`, `skills` meta/deskripsi kategori, `blog` excerpt/UI, metadata SEO, validasi form kontak. **Body MDX blog tetap satu bahasa** (tidak diduplikasi per-locale).

## Prasyarat / konteks kode
- `next-intl` belum terinstal (`package.json` tidak memuatnya); tidak ada `middleware.ts`.
- Teks tersebar di: `src/data/*` (profile, navigation, projects, experience, skills, socials label, blog excerpt) dan hardcode di `Hero/About/Skills/Projects/Experience/Blog/ContactSection`, `Navbar/MobileMenu/Footer`, `app/blog/*`, `app/layout.tsx` (metadata), `app/sitemap.ts`, `lib/jsonld.ts`.
- Campuran bahasa saat ini: hero EN, validasi kontak ID, metadata `locale: id_ID` tapi `<html lang="en">` — selaraskan per-locale setelah migrasi.

## Langkah implementasi (urut)
1. **Instal & versi**: `pnpm add next-intl`; catat versi terinstal (verifikasi kompatibel Next 16 + React 19).
2. **Konfig plugin**: bungkus `next.config.mjs` dengan `createNextIntlPlugin('./src/i18n/request.ts')`; pastikan tetap kompatibel dengan `withMDX` (komposisi `withMDX(withNextIntl(nextConfig))` atau sebaliknya — uji build).
3. **`src/i18n/request.ts`**: `getRequestConfig` baca `requestLocale`, validasi terhadap `['id','en']`, fallback `id`, `setRequestLocale`; import dinamis `messages/${locale}.json`.
4. **`src/i18n/routing.ts`**: `defineRouting({ locales: ['id','en'], defaultLocale: 'id', localePrefix: 'always' })`; export `Link`, `redirect`, `usePathname`, `useRouter`, `getPathname` dari `next-intl/navigation`.
5. **`middleware.ts`** (root): `createMiddleware(routing)`; matcher `'/((?!api|trpc|_next|_vercel|.*\\..*).*)'`. Default `localeDetection: false` (root selalu `/id`, deterministik) kecuali user minta auto-detect.
6. **`messages/id.json` + `messages/en.json`**: namespace `Nav, Hero, About, Skills, Projects, Experience, Blog, Contact, Footer, Metadata, Common, Validation`. Isi `id.json` dari string Indonesia yang ada + terjemahan ID untuk string EN; `en.json` mirror lengkap (jangan ada key hilang).
7. **Restruktur rute**: pindah `src/app/page.tsx`, `src/app/blog/**`, `src/app/sitemap.ts` ke `src/app/[locale]/...`; buat `src/app/[locale]/layout.tsx` (terima `params.locale`, `setRequestLocale(locale)`, `NextIntlClientProvider`, `<html lang={locale}>`, `generateMetadata` per-locale via `getTranslations('Metadata')` + `alternates.languages`). Root `src/app/layout.tsx` jadi shell minimal atau redirect; tambah `generateStaticParams` locale `[{locale:'id'},{locale:'en'}]`. `robots.ts` tetap di root.
8. **Navigasi locale-aware**: `Navbar/MobileMenu/Footer`, semua `Link` internal + anchor `#...` pakai `Link` dari `src/i18n/routing`; label via `useTranslations('Nav')`; `href` nav (`/#home` → perlu prefix locale, mis. `/${locale}/#home` — uji anchor lintas locale).
9. **Section → `useTranslations`**: `Hero/About/Skills/Projects/Experience/Blog/ContactSection` + `blog/page.tsx`, `blog/[slug]/page.tsx` (chrome UI-nya; metadata/slug tetap). Client component pakai `useTranslations`; server component pakai `getTranslations` / teruskan string sebagai props.
10. **Data ber-teks → key messages**: `profile/projects/experience/blog.tsx/skills categoryMeta/socials.label` — pisahkan field non-teks (id, slug, image, url, techStack, period, category key) tetap di `src/data/*`; teks panjang pindah ke messages dengan key stabil (`Projects.items.{id}.title/description/...`, dst.). Komponen resolve via `t('items.' + id + '.title')`. Hapus import teks langsung dari data di komponen yang sudah migrasi; `getPersonSchema()` terima locale/teks terjemahan sebagai argumen (jangan import `profile` ber-teks langsung).
11. **Form kontak**: pindah label/placeholder/error/toast (`Validation.*`, `Contact.*`) ke messages; pesan sukses/gagal Formspree dua bahasa.
12. **Language switcher**: komponen baru (dropdown/toggle ID|EN di Navbar dekat ThemeToggle + footer opsional); gunakan `usePathname` + `router.replace(pathname, { locale })`; pertahankan query/hash bila mudah.
13. **SEO/i18n**: `generateMetadata` per-locale (title/description/keywords OG `locale: id_ID` vs `en_US`); `alternates: { canonical, languages: { id, en } }`; `sitemap.ts` emit URL `/id` + `/en` (home, `/blog`, tiap postingan); `lang` html sinkron locale; JSON-LD `description/jobTitle` per-locale.
14. **Redirect & 404**: verifikasi `/` → `/id`; URL lama tanpa prefix (`/blog`, `/#contact`) redirect dengan benar via middleware; halaman slug invalid tetap `notFound()` per-locale.
15. **Type-safety (opsional tapi disarankan)**: daftarkan tipe messages global next-intl agar key typo ketahuan saat compile.
16. **Verifikasi**: `pnpm lint`, `pnpm build`, `pnpm start`; cek manual `/id`, `/en`, switcher bolak-balik, form kontak dua bahasa, `/sitemap.xml` berisi kedua locale, tidak ada string hardcode tersisa (grep spot-check `"..."` di section/data).

## Risiko / jebakan
- Komposisi `withMDX` + plugin next-intl bisa bentrok — uji build tiap ubah config.
- Anchor `/#section` + prefix locale: link harus pertahankan locale aktif; test klik nav di `/en` tidak mental ke `/id`.
- `blog/[slug]/generateMetadata` + `generateStaticParams` sekarang dua dimensi (locale × slug) — jangan lupa kombinasi keduanya.
- Key messages tidak sinkron id/en → runtime missing-message; extraction/cek manual wajib sampai ada tooling.
- `localeDetection: false` vs `true`: false = deterministik (`/` → `/id` selalu); true = hormati header browser tapi perilaku root tidak deterministik. Default false.

## Validasi (definisi selesai)
- `pnpm build` + `lint` hijau; tidak ada `next-intl` missing-message di log.
- Semua rute hanya hidup di `/id/*` dan `/en/*`; `/` redirect ke `/id`.
- Ganti bahasa via switcher mempertahankan halaman; seluruh teks terlihat (hero, about, skills, projects+modal, experience, blog list/detail, contact, nav, footer) berganti bahasa.
- Sitemap berisi entri `/id` dan `/en`; `<html lang>` benar per-locale.

## Pertanyaan terbuka (untuk implementor/user)
- Konfirmasi cakupan penuh incl. data (asumsi plan ini) vs UI-chrome saja.
- Body MDX blog mau diduplikasi per-locale (`content/blog/id|en`) sekarang atau nanti?
- `localeDetection` tetap `false` atau ikuti bahasa browser?

# Bagian 2 — PayloadCMS (monolit Next, semua konten, media Neon Object Storage)

## Keputusan (disepakati)
- CMS: **Payload v3** (self-hosted, open-source) — lokalisasi field-level `id`/`en`, relasi projects/experience, media upload, single admin. (Ringan kalah: Decap tanpa DB tapi i18n file duplikat manual; Tina/Sanity visual MDX/hosted di luar repo.)
- Pola: **monolit Next** — Payload + frontend satu app, admin di `/admin`, frontend baca via Local API.
- Infra: **Vercel + Neon Postgres + Neon Object Storage** (S3-compatible, satu vendor) via `@payloadcms/storage-s3`; filesystem Vercel ephemeral jadi media tidak boleh lokal saat prod. Bucket `public_read` untuk media publik, kredensial branch-scoped (`AWS_ENDPOINT_URL_S3`, `AWS_ACCESS_KEY_ID`=`token_id`, `AWS_SECRET_ACCESS_KEY`, `forcePathStyle: true`).
- Cakupan: **semua konten** (blog, projects, experience, profile) via editor visual; upload gambar via CMS (cover blog, screenshot proyek, foto profil) ke Neon Object Storage (bukan `public/`).
- Auth: single admin, email-password bawaan Payload, tanpa peran.

## Rekomendasi ya/tidak
**Ya, Payload direkomendasikan** untuk kebutuhan ini (editor visual + semua konten + media + dua bahasa). Harga: butuh proyek Neon (Postgres + Object Storage) + migrasi MDX/messages → koleksi; build lebih berat (Payload + sharp + drizzle). Satu vendor: DB dan media sama-sama di Neon, kredensial branch-scoped yang sama.

## Arsitektur target
- `payload.config.ts` (root): `db: postgresAdapter` (Neon `DATABASE_URL`), `localization: { locales: ['id','en'], defaultLocale: 'id', fallback: true }`, `secret: PAYLOAD_SECRET`, sharp, `s3Storage` (`@payloadcms/storage-s3`) arahkan ke endpoint Neon Object Storage (`AWS_ENDPOINT_URL_S3` + `forcePathStyle: true`), admin route `/admin`.
- Koleksi: `users` (admin tunggal), `media` (upload, `imageSizes` thumbnail/card, alt localized), `posts` (blog: **slug non-lokal stabil sama dua locale**, title/excerpt/content localized, cover→media, category, date, readTime, `versions.drafts: true` + preview), `projects` (key stabil `project-1..n`, field teks localized, techStack array, category, githubUrl/demoUrl, image→media), `experiences` (key `exp-1..n`, role/description/achievements localized, institution/period/type non-lokal), `profile` sebagai **global** (bukan koleksi; single dokumen: bio/tagline/values localized, foto→media).
- Migrasi MDX: **konversi manual sekali** via seed script — 3 postingan ditulis ulang ke Lexical JSON (slug stabil, `Callout`→blocks, code fence→block code); verifikasi tampil identik.
- Draft preview: **ya** — `versions.drafts` + rute `/api/preview` + `draftMode`, tombol preview per locale di admin.
- Admin di **`/admin` root** (di luar `[locale]`); matcher middleware next-intl kecualikan `admin` + `api`.
- Frontend `app/[locale]/*`: ganti sumber `src/data/*` + `import MDX` dengan query Payload Local API per `locale` (`payload.find({ locale })`); listing blog + `generateStaticParams` locale×slug dari Payload; detail post render Lexical richText (bukan MDX) — komponen `Callout`/`Pre` dipetakan ulang ke blocks/serializer Lexical.
- `messages/*.json` tetap untuk **chrome UI** (Nav, label section, form, footer, Metadata); **isi konten** pindah ke Payload. Jangan duplikasi isi di dua tempat.
- Sitemap/JSON-LD/metadata per-locale baca dari Payload (tanpa fallback konten basi bila DB gagal — tampilkan error/notFound jujur per-locale; chrome UI dari messages tetap render).
- Render: **static + on-demand revalidate** — `generateStaticParams` locale×slug, halaman konten cache per locale+slug, webhook Payload (`afterChange` publish/unpublish) panggil `revalidateTag` agar update instan tanpa rebuild.

## Langkah implementasi (urut)
1. **Dependensi**: `pnpm add payload @payloadcms/next @payloadcms/db-postgres @payloadcms/storage-s3 @payloadcms/richtext-lexical sharp` (nama paket storage v3 = `@payloadcms/storage-s3`, bukan `plugin-s3` era v2 — verifikasi saat instal). Uji kompatibel Next 16 + React 19 + `withMDX` + plugin next-intl (`createNextIntlPlugin`) — build tiap tahap. Catatan: docs payloadcms.com gagal di-fetch saat penulisan plan (semua pola URL 404); implementor wajib cek docs terbaru untuk API `withPayload`/`buildConfig` versi terinstal.
2. **Env**: `DATABASE_URL` (Neon Postgres), `PAYLOAD_SECRET` (acak panjang), `AWS_ENDPOINT_URL_S3` + `AWS_ACCESS_KEY_ID` (`token_id` kredensial Neon scope `storage:read/write`) + `AWS_SECRET_ACCESS_KEY` + `AWS_REGION` + nama bucket (Neon Object Storage, `public_read` untuk media publik), `NEXT_PUBLIC_BASE_URL` tetap; tambah contoh ke `.env.example` (tanpa nilai rahasia).
3. **`payload.config.ts`**: postgresAdapter pool `DATABASE_URL`, localization id/en default id fallback true, koleksi di atas, media→`s3Storage` ke Neon Object Storage (`disableLocalStorage` otomatis `true` oleh plugin; `clientUploads: true` karena batas upload server Vercel 4,5 MB + CORS PUT dari domain situs), admin `/admin`, akses publik read-only konten published + write wajib login.
4. **Rute admin**: mount Payload admin + REST (`/admin`, `/api/*`) di app yang sama tanpa prefix locale (kecualikan dari middleware next-intl agar tidak redirect ke `/id`).
5. **Migrasi data (seed sekali)**: skrip seed impor 3 MDX + `messages` konten (projects/experience/profile/blog excerpt) ke koleksi Payload dua locale; media awal (cover/profil/proyek) upload via admin atau `filePath` seed; verifikasi tiap locale lengkap, slug stabil sama.
6. **Lapisan baca**: helper `src/lib/cms.ts` (`getPosts`, `getPostBySlug`, `getProjects`, `getExperiences`, `getProfile`) via Local API + `locale`; cache/tag revalidasi (`revalidateTag`/webhook Payload) agar publish dari admin memutakhirkan halaman tanpa rebuild penuh.
7. **Halaman**: `blog/page.tsx`, `blog/[slug]/page.tsx`, section Projects/Experience/Hero/About/Blog baca dari helper (server component `getTranslations` untuk chrome + data CMS untuk isi); `generateStaticParams` locale×slug dari Payload; slug invalid `notFound()` per-locale.
8. **Rich text blog**: render Lexical → React; sediakan blocks/callout setara `Callout`/`Pre`/code fence; uji 3 postingan hasil migrasi tampil identik (tip box, code block TS).
9. **Media**: `next.config.mjs` `images.remotePatterns` untuk endpoint Neon Object Storage (`*.storage.*.aws.neon.tech` sesuai branch endpoint); `Image` pakai URL CMS + `alt` localized; thumbnail admin `adminThumbnail`. Batasan Neon: path-style only (`forcePathStyle: true`), region terbatas (us-east-1/2, eu-central-1, ap-southeast-1), free plan 5 GB/proyek, rate-limit `503 SlowDown` saat trafik berat — implementor catat retry/backoff bila perlu.
10. **SEO/i18n**: metadata/sitemap/JSON-LD per-locale dari CMS; `alternates.languages` id/en; OG `locale` id_ID/en_US; sitemap emit `/id`+`/en` dari slug Payload.
11. **Akses & keamanan**: kunci API internal bila perlu; `read` publik hanya published; admin login single user; cek `PAYLOAD_SECRET` prod panjang; secure cookie di prod.
12. **Fallback & rollback**: hanya selama migrasi — MDX/messages lama dipertahankan sampai seed terverifikasi, lalu diarsipkan (bukan fallback permanen). Setelah CMS live: DB gagal → error/notFound jujur per-locale, bukan konten basi. Webhook revalidate: `afterChange` pada posts/projects/experiences/profile → `revalidateTag('cms-{collection}-{locale}')`; halaman subscribe tag tersebut.
13. **Verifikasi**: `pnpm lint/build/start`; cek `/admin` login, CRUD tiap koleksi dua locale, upload tampil di frontend, publish draft→live via revalidate, `/id`+`/en` penuh, sitemap dua locale, `html lang` benar.

## Risiko / jebakan
- Monolit + Vercel: bundle Payload berat, cold start naik; `output: standalone` sudah ada + uji waktu build.
- Komposisi config tiga lapis `withPayload(withNextIntl(withMDX(nextConfig)))` (atau urutan per docs versi terinstal) — bentrok paling mungkin di tahap ini; uji build tiap bungkus.
- Middleware next-intl `always` (dibuat di Bagian 1, matcher awal `/((?!api|trpc|_next|_vercel|.*\\..*).*)`) bisa membajak `/admin` — saat mount Payload, pastikan matcher kecualikan `admin` juga, atau taruh rute admin di luar `[locale]`.
- Neon Object Storage endpoint **branch-scoped**: kredensial dibuat di branch `main` tidak valid untuk branch lain di luar lineage-nya. Env Vercel Production (branch main) vs Preview (branch preview) perlu kredensial masing-masing — jangan satu kredensial untuk semua env.
- `clientUploads: true` butuh CORS PUT dari domain situs di bucket Neon; tanpa ini upload admin dari browser gagal.
- Migrasi `localized: true` mengubah struktur data; seed dua locale wajib lengkap atau fallback menutupi kekosongan tanpa sadar.
- Lexical ≠ MDX: `Callout`/`Pre` MDX tidak otomatis ikut; butuh serializer/blocks pengganti.
- Neon cold start + pool serverless: gunakan pooled connection string; batasi `depth` query berelasi.

## Validasi (definisi selesai)
- `/admin` login single admin; CRUD + upload media dua locale tersimpan di Neon Object Storage (bukan lokal, bukan R2/S3 eksternal).
- Seluruh konten (blog list/detail, projects+modal, experience, hero/about) tampil dari CMS di `/id` dan `/en`; chrome UI tetap dari messages.
- Publish/unpublish dari admin memutakhirkan frontend (revalidate) tanpa deploy ulang.
- `build`+`lint` hijau; sitemap berisi `/id`+`/en`; tidak ada konten ganda MDX vs CMS yang aktif bersamaan.
